The Cadence brain

A deep real-time brain that learns from experience.

Start with a direct response, connect learned representations, or add observers that examine internal prediction error. Every Cadence layout settles with the same patch rule and can learn from experience.

The architecture

One rule. Different ways to respond.

A Cadence brain is made of bounded, self-reading patches: local state, incoming ports, predictions and records of experience. Each patch compares its state with its prediction and participates in repair.

01 / Read

Local models

Each population has access to selected observations and connections. Ports define what it can read.

02 / Connect

Choose the wiring

Read inputs directly, connect live states, or observe states and exact errors. Wiring gives each population its role.

03 / Settle

A settled answer

Input-only states settle independently. Connected populations settle together. The same numerical qualification applies to both.

04 / Learn

Experience persists

Accepted teaching and experience update local models. Explicit learning and memory mechanisms support further practice.

Cadence's Cortex and Brain interfaces expose this shared mathematical substrate. Flat responses, state connections and recursive observers can coexist in one brain.

The research takes inspiration from cooperating cortical models. Practised responses, coordination and reflective checking offer useful analogies for the three patterns. These are functional analogies, not a biological model.

Three design patterns / One patch rule

Choose the brain
the task needs.

Flat, state-coupled and recursive layouts all learn and settle through the same mathematical substrate.

01

Flat settlement.

Practised response / Muscle memory

Think of a familiar movement becoming a direct response. Patches read sensory inputs directly: a small, inexpensive starting point for learning simple prediction and control relations.

02

State-coupled settlement.

Coordination / Balance

Think of several parts adjusting together. Populations read other populations' live states, so learned intermediate representations can respond to one another during settlement.

03

Recursive observer settlement.

Reflective reasoning

Think of checking an interpretation against its mismatches. Observers read states and exact prediction errors; another observer can read those observers in the same settlement.

Spend computation where it helps.

Flat layouts offer an inexpensive starting point for direct responses. State coupling and recursive error readback introduce richer interactions, whose benefit and settling cost depend on the task. Measure query latency and learning cost separately.

All three are working design patterns in Cadence 0.50.0. The analogies describe their roles, not biological equivalence or a ranking of intelligence. Start with the least expensive layout that learns the behavior, then measure what extra connections add.

The building block

One small predictive unit.

Each patch holds a state and learned relation parameters. Its ports carry incoming signals. The difference between its state and its prediction is its prediction error.

The design choice

Decide what each patch reads.

Flat patches read external inputs. Composed populations also read live states. Recursive observers read states and exact errors, including those of other observers.

The common answer

Settle, then read the state.

Every pattern repairs its internal state with the same rule. State and error connections can send influence back through the objective. Supplied sensory values stay fixed.

What the animation means

Same rule. Different routes to an answer.

In flat mode, each patch settles its own relation to the inputs. In state-coupled mode, a later constraint can revise an earlier state. In recursive mode, exact prediction-error signals also participate; select two levels to see observers observing observers.

The returning arrows show influence through the objective's derivatives, not additional learned reverse edges. Changing the sensory signal retains activity until you repair or reset it. Changing the layout starts a fresh illustration.

Answering and learning

Settling changes activity. Learning changes relations.

For a query, weights and biases stay fixed while internal states settle. When Cadence admits an experience, supplied outcomes can constrain outputs and the relation parameters can change too, anchored to their values before that experience.

All three patterns use that learning API. This illustration keeps parameters fixed so you can isolate settlement. Observer depth, repair steps and prediction into the future are three different things.

The patch equations behind the illustration

predictionᵢ = tanh(biasᵢ + Σ weightᵢⱼ × signalⱼ)
errorᵢ = stateᵢ − predictionᵢ
objective = ½ Σ errorᵢ² + 0.18/2 × Σ stateᵢ²

A signal can be a supplied input, another patch's state or an observed prediction error. Predictions and errors are recomputed from the current state; errors cannot be adjusted independently to conceal disagreement.

The illustration uses bounded state updates, exact derivatives through the error readbacks and backtracking for objective decrease. It stops at its stationarity tolerance or a 240-step budget. The objective's numerical “energy” does not measure electrical energy.

The positive activity penalty matters. For the corresponding acyclic, unclamped model in the idealized zero-penalty limit, the stationary answer reduces to forward substitution. Positive penalties or output constraints allow a different compromise. That difference alone does not establish better task performance.

The product direction

A brain that stays in the loop.

We want robots to learn through operation, adapt when their body or environment changes, and preserve useful experience.

The first product engagement targets a bounded adaptation problem. The larger ambition is a reusable brain across bodies and tasks, with efficient deployment after bootstrapping.

Control-loop latency, retained skills and electrical energy per useful action are measurements for each deployment. The software evidence below gives us a starting point for those tests.
