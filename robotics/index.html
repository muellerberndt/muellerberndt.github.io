Why a learning brain

Built like a brain. Made for a body.

Animal and human brains learn from experience and not by backpropagation with gradient descent. Cadence is designed the same way: its connections change locally while the brain keeps running.

On the job

It learns while it works.

The same brain acts and learns from every measured outcome. There is no training phase before deployment and no difference between training and inference.

Changed conditions

It adapts when the body changes.

A worn actuator, a new payload or a different surface shows up in what the robot measures. The live brain adjusts from those measurements, without being told what changed.

Local learning

It learns the way brains do.

Each connection changes from the activity of the two units it joins. There is no backward pass through the network, so learning can run on the robot itself.

Memory

It remembers.

A working trace carries the recent past and an associative memory keeps what mattered. One experience is recorded, and the next decision in that situation reads it.

Settled answers

It acts only on a settled answer.

Every action is the settled state of the whole brain. A brain that does not settle refuses to act, so a controller can fall back instead of executing a guess.

Inspection

It shows its work.

The activity of every region can be read while the brain runs. Private imagination tests a response to a situation before the body commits to it.

Shown in simulation today in Rover Lab, Patch World and the Atari Arcade. Cadence 0.70 is experimental research software, and a physical robot evaluation is the next test.

Rover Lab / Working simulation

Change the body. Watch it adapt.

Weaken a simulated rover's right wheel and watch its model learn the changed response.

Cadence learns how wheel commands turn into motion, beside a frozen copy, an adaptive estimator and a small neural baseline. In a two-seed development screen on Cadence 0.70, learning Cadence reached 10/10 weakened-body targets, against 5/10 for its frozen copy. The adaptive estimator also reached 10/10.

The simulation uses four-patch body models with a supplied action selector. Physical robot evaluation is a proposed next test.

A paid evaluation

Test one problem worth solving.

An altered actuator response, a changed payload or a recurring recovery task can make a useful starting point. Choose a failure your team can reproduce and a result it can measure.

01

Define the task

Name the technical sponsor and agree the observations, available experience and success criteria.

02

Connect the brain

Integrate a simulator or robot interface. Specify Cadence's decisions and measure the full sensing-to-command path.

03

Measure useful work

Compare with your existing stack and adaptive baselines. Measure completion, interventions, recovery experience, retained skills and compute cost.

04

Choose deployment

Review reproducible results together. Useful results can lead to production integration and recurring runtime and embodiment licensing.
